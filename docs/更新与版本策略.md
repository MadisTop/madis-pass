# 更新与版本策略（客户端已实现，服务未启用）

本文件说明 Madis Pass 在线更新客户端的**实际实现**、相邻 JSON 文件的字段含义，以及启用前必须补齐的条件。JSON 标准不支持注释，因此 `update-metadata.json` 与 `version-policy-v2.json` 顶部不写注释，说明统一放在本文档。

> **当前状态：客户端代码已实现并纳入测试，但服务默认关闭，程序启动后不发起任何网络请求。**
> `release.config.json` 的 `updates.state` 为 `client-implemented-trust-root-not-configured`，`enabled` 与 `automaticInstall` 均为 `false`，`trustedPublicKey` 为空字符串。仓库内**不存在**任何私钥、`.minisig` 文件、伪造公钥或伪造的包摘要 / URL。

## 1. 信任边界：密文库零网络

- `pass-crypto` / `pass-store` / `pass-service` 不依赖更新模块，也不链接 HTTP 栈；密文库的读写、KDF 与备份路径完全离线。
- `apps/desktop/src/update.rs` 是本进程**唯一**的出站通道，只访问编译期固定的官方 HTTPS 端点，不读取环境、响应或用户输入中的 URL 来覆盖端点，请求不携带本地数据、库标识、遥测或凭据。
- 编译期信任根 `OFFICIAL_PUBLIC_KEY` 当前为 `None`：`enabled()` 返回 `false`，后台检查线程不会启动，界面显示「自动更新服务尚未启用」。**没有配置信任根时绝不退化为「不验签也能下载」**。
- `ureq 3` 配置为 `https_only`、`max_redirects=0`、`proxy(None)`、全局超时，并对元数据 / 签名 / 安装包设置硬上限，防止恶意响应耗尽资源。

## 2. 客户端已实现的能力

| 能力 | 实现 |
| --- | --- |
| 固定端点 | `https://raw.githubusercontent.com/MadisTop/madis-pass/main/update-metadata.json` 及同名 `.minisig`；包 URL 必须严格位于 `https://github.com/MadisTop/madis-pass/releases/latest/download/` 之下 |
| 签名验证 | Minisign legacy `Ed` 公钥（`Ed` + 8 字节 key id + 32 字节 Ed25519 公钥）与签名文件；key id 不匹配、签名结构错误、公钥为低阶点一律拒绝 |
| 元数据校验 | `schemaVersion == 2`、`identifier == top.madis.pass`、未知字段一律拒绝（`deny_unknown_fields`） |
| 拒绝降级 | 只接受纯数字三段版本号，拒绝预发布后缀；远端版本不高于当前版本即返回「无可安装更新」，即使签名有效也不降级 |
| 包白名单 | `target` / `os` / `arch` / `format` 必须与本机目标一致；文件名以 `madis-pass` 开头且不含路径分隔符或 `..`；URL 尾段必须等于文件名 |
| 完整性 | 大小不超过 64 MiB 且与元数据一致；SHA-256 必须为 64 位小写十六进制；下载后先比大小、再比摘要、最后验独立签名，全部通过才写入缓存 |
| 并发控制 | 状态机保证同一时刻只有一个检查 / 下载线程；只有本轮成功验签才允许安装按钮 |
| 检查时机 | 启动 15 秒后首次后台检查，之后最多每 12 小时一次；也可在设置页手动检查。锁定态同样检查，但检查过程不接触密文库 |
| 便携模式 | 只提示可用版本，**不下载、不创建缓存、不准备安装载荷**；便携目录可能被移动或位于同步盘，自动覆盖会破坏密文库 |
| 安装交接 | 先完整锁定密文库、撤销剪贴板、写回偏好，再启动自身 `--update-helper`；助手等待主进程退出后按格式安装并重启 |
| 安装格式 | NSIS `/S`、MSI `msiexec /quiet`、AppImage 暂存后原子替换、macOS `app.tar.gz` 解压替换 bundle 并保留旧版；deb / rpm / dmg 明确拒绝自动安装，保留已验签文件并提示手动处理 |
| 失败处理 | 交接失败回到可重试状态，半写入的暂存包被丢弃；错误文案只含固定原因码，不渲染路径或远端正文 |
| 手动入口 | 设置页提供官方下载页与国内 Gitee 镜像页两个固定入口；**镜像不参与验签信任链** |

数据保护：更新只替换程序文件，不改动、不删除 `%LOCALAPPDATA%\Madis\Pass\Data`（及 macOS / Linux 对应数据目录）。重启参数会剔除 `--smoke-test`。

## 3. 客户端**尚未**实现的部分

- `version-policy-v2.json` 中的 `sequence` 单调递增策略、`offlineGraceDays: 14` 离线宽限、旧版本截止与 `latest` 指针推进逻辑：客户端目前**不读取**该文件，这些字段是发布侧的占位契约。
- 官方下载网关、匿名回读校验、双端发布顺序、Release 清理：属于发布流水线，不在客户端。
- 后台静默安装：安装必须由用户在设置页点击，并在退出后交接，不自动杀进程。

## 4. 签名绑定字段与发布顺序（目标流程）

元数据签名必须覆盖以下字段，任何字段被篡改都应导致验签或身份核对失败：

`identifier`、`version`、`target`、`os`、`arch`、`format`、`name`、`size`、`sha256`、`url`、`signature`。

其中 `identifier` 固定为 `top.madis.pass`，`name` / `sha256` / `url` 必须与真实包逐字节一致；摘要只用于检测损坏与绑定身份，不能替代签名。

将来启用时的发布顺序：

1. `packages`：先发布全部安装包文件。
2. `signatures-and-bound-metadata`：对每个包生成 `.minisig` 并发布已签名的绑定元数据。
3. `readback-verification`：从公开端点匿名回读包、签名与元数据，核对字节数、SHA-256 与签名。
4. `latest`：全部回读成功后才更新 `latest` / 元数据指针。

任何一步失败都保留上一可用版本，不提前删除历史记录，也不推进指针。

## 5. 信任根与相邻 JSON

- 信任根必须是本项目**独立生成**的 Minisign 公钥，不复用其它项目或产品的凭据；公钥随客户端编译期固定，私钥离线保管，绝不入库、不入 CI 日志。
- `update-metadata.json`：`schemaVersion: 2`，`identifier: top.madis.pass`，`version: 0.1.0`，`packages: []` 为空数组——表示**当前没有任何已发布、已签名的更新包**。
- `version-policy-v2.json`：`sequence: 0` 表示尚无已签发策略，`generatedAt` 为模板基准时间 `2026-11-12T00:00:00Z`，`releases` 中只有 `0.1.0` 且 `state` 为 `not-published`、`releasedAt` 为 `null`。
- **不创建任何 `.minisig` 文件**，也不伪造签名、公钥、真实包 SHA-256 或下载 URL。

## 6. 启用前置条件

1. 生成独立 Minisign 密钥对，把公钥写入客户端编译期常量与 `release.config.json` 的 `trustedPublicKey`，私钥离线保管。
2. 部署匿名 HTTPS 元数据端点与网关，完成上述发布顺序与匿名回读。
3. 用真实包完成跨版本实机升级闭环：检查 → 验签 → 下载 → 退出交接 → 安装 → 重启 → 密文库可解锁。
4. 单独验收拒绝降级、故障回滚、便携模式不安装、离线场景不阻断启动。
5. 全部通过后，才把 `enabled` / `automaticInstall` 改为 `true` 并更新 `updates.state`。

上述任一项未完成前，客户端保持默认关闭。单元测试与状态机测试**不是**签名材料或实机升级验收。

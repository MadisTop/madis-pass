# MPV1 密文格式规范（公开）

> 状态：**规范 v1，设计冻结；尚无实现、尚无测试向量**。
> 本文件是 Madis Pass 密文库格式的**唯一对外权威文本**，用于让第三方在不依赖本产品源码的情况下独立验证或读取密文库。
> 本文件是规范文档，**不含实现源码**；Madis Pass 的程序源码为私有。格式若变更，本文件与格式版本同步更新。

## 1. 范围与约定

- 文件默认名 `pass.mpv1`，位于产品数据目录；便携模式下位于可执行文件旁 `Data/`。
- 所有多字节整数为**小端（little-endian）**；所有长度单位为字节；`u8`/`u16`/`u32`/`u64` 为无符号定宽整数。
- 「必须」表示不符合即拒绝；「不得」表示禁止实现；「应当」为建议。
- 本规范只定义静态文件格式，**不定义**文件同步、冲突合并或跨设备一致性；密文库由用户自行搬运。

## 2. 文件整体结构

~~~text
┌──────────────────────────────┐
│ 头 header        88 字节      │  明文，但整体作为 AEAD 的 AAD
├──────────────────────────────┤
│ ciphertext       N-16 字节    │  载荷明文的加密结果
│ Poly1305 tag     16 字节      │  认证标签
└──────────────────────────────┘
文件总长度 = 88 + N，其中 N = ciphertext_len（含 16 字节标签）
~~~

## 3. 头字段（固定 88 字节）

| 偏移 | 长度 | 字段 | 类型 | 值 / 约束 |
| --- | --- | --- | --- | --- |
| 0 | 4 | `magic` | ASCII | 必须为 `MPV1`（`4D 50 56 31`） |
| 4 | 2 | `format_version` | u16 | 必须为 `1` |
| 6 | 2 | `flags` | u16 | 必须为 `0`；未知位一律拒绝 |
| 8 | 1 | `kdf_id` | u8 | `1` = Argon2id v1.3 |
| 9 | 1 | `cipher_id` | u8 | `1` = XChaCha20-Poly1305 |
| 10 | 2 | `reserved` | u8[2] | 必须为 `00 00` |
| 12 | 4 | `kdf_memory_kib` | u32 | KDF 内存成本，单位 KiB；本版本为 `65536`（64 MiB） |
| 16 | 4 | `kdf_iterations` | u32 | 迭代次数；本版本为 `3` |
| 20 | 1 | `kdf_parallelism` | u8 | 并行度；本版本为 `4` |
| 21 | 3 | `reserved2` | u8[3] | 必须为全 `00` |
| 24 | 16 | `kdf_salt` | u8[16] | 每次保存由 OS CSPRNG 新生成 |
| 40 | 24 | `aead_nonce` | u8[24] | 每次保存由 OS CSPRNG 新生成 |
| 64 | 8 | `ciphertext_len` | u64 | AEAD 输出长度，**含 16 字节标签** |
| 72 | 4 | `header_size` | u32 | 必须为 `88` |
| 76 | 12 | `reserved3` | u8[12] | 必须为全 `00` |

`header_size` 用于让读取器明确 AAD 边界；读取器不得假设未来版本头仍是 88 字节，遇到未知 `format_version` 必须拒绝而不是猜测。

## 4. 读取前的无秘密校验

读取器必须在运行 KDF **之前**完成以下检查（顺序不限，但都必须在分配 KDF 内存前）：

1. `magic`、`format_version=1`、`flags=0`、三个保留字段全零、`header_size=88` 精确匹配。
2. `kdf_id=1` 且 `cipher_id=1`；未知值拒绝，**不得**降级到更弱算法。
3. 文件实际长度严格等于 `88 + ciphertext_len`；`ciphertext_len` 至少为 16，且不得超过读取器设定的上限。
4. KDF 参数在允许范围内（建议范围：`kdf_memory_kib` 19456–1048576、`kdf_iterations` 1–10、`kdf_parallelism` 1–16）；超出即拒绝，**不得**按头中数值分配内存，以防恶意文件造成资源耗尽。

任一检查失败：拒绝解锁，不尝试修复、不重建库、不回退参数。

## 5. 密钥派生

输入：用户主密码的 **UTF-8 字节序列**（不做 Unicode 归一化、不加盐前缀、不截断）、头中的 `kdf_salt` 与 KDF 参数。

1. `master_key = Argon2id(version=0x13, variant=id, password=主密码UTF-8, salt=kdf_salt, m=kdf_memory_kib, t=kdf_iterations, p=kdf_parallelism, output_len=32)`
   - 本版本固定 `m=65536 KiB`、`t=3`、`p=4`。该档位为 RFC 9106 第二推荐档；解锁过程按设计占用约 64 MiB 以上内存并消耗 CPU，这是抗离线爆破成本，不是性能缺陷。
2. `enc_key = HKDF-SHA256(ikm=master_key, salt=kdf_salt, info="madis-pass/mpv1/enc/v1", output_len=32)`
   - `info` 为上述 ASCII 字符串，不含结尾 NUL。
3. `master_key` 与 `enc_key` **不得**写入文件、日志或任何持久化介质；使用完毕后应清零。

不存储主密码校验哈希或「密码提示」。主密码是否正确由第 7 步的标签校验判定。

## 6. AEAD 加解密

| 项 | 值 |
| --- | --- |
| 算法 | XChaCha20-Poly1305（RFC 8439 的 XChaCha20 扩展 nonce 变体） |
| 密钥 | 第 5 步派生的 32 字节 `enc_key` |
| nonce | 头中 24 字节 `aead_nonce` |
| AAD | **完整 88 字节头**（偏移 0–87，按文件中原始字节） |
| 输出 | `ciphertext ‖ 16 字节 Poly1305 标签`，长度即 `ciphertext_len` |

把整段头作为 AAD 的意义：KDF 参数、盐、nonce、长度、版本与保留位任何一位被改动，标签校验都会失败，攻击者无法静默降级参数或篡改长度。

**加密**：每次保存生成新 `kdf_salt` 与 `aead_nonce`；按第 5 步派生密钥；用规范化 JSON 明文加密；先写头再写密文与标签。即使内容未变，两次保存的密文也必须不同。

**解密**：先验头（第 4 步）→ 派生密钥 → 以头为 AAD 验证并解密 → 得到载荷明文。标签校验失败、长度不符、参数不合法、格式版本未知，在用户侧统一表现为「解锁失败」，实现不得通过不同文案或不同耗时区分「主密码错误」与「文件损坏」。

## 7. 载荷明文：规范化 JSON

载荷为单个 UTF-8 JSON 对象，遵循以下规范化规则，使不同实现可以产生一致字节：

- 对象键按 **Unicode 码位字典序**排列；不使用 `preserve_order` 之类的保留插入序行为。
- 无多余空白、无缩进、无尾随换行；字符串按 JSON 标准转义，非 ASCII 字符直接以 UTF-8 输出（不使用 `\u` 转义）。
- **不使用浮点数**；所有计数为 u32/u64 整数，所有时间为字符串。
- 布尔值只用 `true` / `false`；空值用 `null`，不省略约定的键。
- 不允许未知顶层键参与本版本；读取器遇到未知顶层键应拒绝，不得静默丢弃。

顶层对象：

| 键 | 类型 | 说明 |
| --- | --- | --- |
| `created_at` | string | RFC 3339 UTC，如 `2026-11-12T09:00:00Z` |
| `entries` | array | 条目数组，见下表 |
| `format` | string | 固定 `mpv1` |
| `meta` | object | 非秘密元数据（如生成器默认值） |
| `revision` | u64 | 每次成功保存 +1，不得回退写入 |
| `schema` | u32 | 载荷 schema，本版本为 `1` |
| `settings` | object | 自动锁定、剪贴板、生成器、快捷键等安全相关设置 |
| `updated_at` | string | RFC 3339 UTC |
| `vault_id` | string | UUIDv4，建库时生成，重建库不得复用 |

`entries[]` 元素：

| 键 | 类型 | 约束 |
| --- | --- | --- |
| `created_at` / `updated_at` | string | RFC 3339 UTC |
| `custom_fields` | array | 元素 `{ "key": string, "protected": bool, "value": string }`；`protected=true` 的 value 按密码同样保护 |
| `favorite` | bool | 仅用于置顶排序 |
| `id` | string | UUIDv4，库内唯一 |
| `notes` | string | 可空，最长 65536 字符 |
| `password` | string | 可空，最长 4096 字符；**主要敏感字段** |
| `tags` | array\<string\> | 去重，最多 32 项，单项最长 64 字符 |
| `title` | string | 去首尾空白后非空，最长 256 字符 |
| `url` | string | 可空，最长 2048 字符；读取器不得对其发起网络请求 |
| `username` | string | 可空，最长 512 字符 |

示例（仅示意结构，**不是真实数据**，也非测试向量）：

~~~json
{"created_at":"2026-11-12T09:00:00Z","entries":[],"format":"mpv1","meta":{},"revision":1,"schema":1,"settings":{},"updated_at":"2026-11-12T09:00:00Z","vault_id":"00000000-0000-4000-8000-000000000000"}
~~~

## 8. 完整性、备份与修订

- 备份文件与主文件**同格式、同密钥**，可直接改名读取。
- 每次成功保存递增 `revision`。产品可在本地无秘密状态中记录最后见到的 `revision`，若打开的文件 `revision` 更低应提示可能存在回滚；该状态是普通本地文件，**不是硬件安全存储**，不构成防回滚保证。
- 写入采用「同目录临时密文文件 → 刷盘 → 原子替换」；任何时候磁盘上都不应出现明文中间文件。

## 9. 版本演进

- `format_version` 或 `schema` 未知值一律拒绝；不得「尽力兼容」。
- KDF 算法、AEAD 算法、头布局、AAD 定义或 JSON 顶层结构的任何破坏性变更，都必须提升格式版本、更新本规范、公开新的测试向量，并提供显式迁移工具。
- 允许通过头中的 `flags` 引入向后兼容的可选能力，但 v1 中 `flags` 必须为 `0`。

## 10. 独立校验工具与测试向量

- `madis-pass-probe` 是独立编译、独立分发的命令行工具，提供头解析、格式校验与标签验证，其解析代码与产品实现走不同路径，用于验证本规范不是实现代码的镜像描述。
- **当前状态**：实现与固定测试向量尚未发布。首个实现提交时应同步公开一组不含真实凭据的固定测试向量（正确主密码、错误主密码、各类篡改样本），并以 probe 与实现双向互校。
- 第三方实现若与本规范或测试向量不一致，应以本规范为准并报告差异，不得由产品实现反向修改规范来「对齐」。

## 11. 安全边界

本规范保证的是**静态密文文件的机密性与完整性**：在正确主密码下可解密，任何位篡改或参数篡改会被标签校验发现，离线爆破需付出 Argon2id 的内存与时间成本。

本规范**不保证**：防御本机管理员或同用户恶意软件、键盘记录器、屏幕截图/录屏、剪贴板历史、系统页面文件与休眠文件、崩溃转储、冷启动攻击、文件系统快照与云同步历史副本、旧密文备份、物理硬件攻击或侧信道攻击；也**不提供**主密码找回、重置或提示。Madis Pass 的程序源码为私有，公开的是本规范与独立校验工具，产品未经第三方安全审计。

完整的产品侧披露见本仓 `README.md` / `README.zh-CN.md` 的「安全边界」章节。
